# M02_S05.002.REDESIGN — 并发（activity）视图

## 1. 用户原话与范围确认

> 并发页面应该重新好好设计下

经 AskUserQuestion 确认两项：**(1) 加 live hero 数字、替掉三按钮图例**；**(2) 图表右缘留空，旁边给 live 数字**。
（Go 修复 + 拆 y 轴 + 阶梯线 + 删死代码 为三个候选方案的共同基础，不在选项内。）

## 2. 先查出来的 bug：右缘恒为 0

调查阶段用 Go probe 证明：**每个 history window 的最后一个点结构性恒为 0**，与输入无关。

```
19 个会话全部在跑：  prev(11:30)=19  →  FINAL(12:00)=0
span 结束于 now 之前 / 恰好 now / now 之后 —— 三种都是 0
```

实机同时刻：`summary.active_sessions=19`，而图表右缘一头扎到 0。
每个窗口里**唯一**的 0 就是最后一个点（1D idx 48/48、7D 56/56、30D 60/60）。同样的 span 喂给 `peakConcurrency` 正确返回 19，所以问题被隔离在 `concurrencySeries` 的末点，不在 span 数据。

UI 当时是**把它藏起来**而不是修：`selectedTrendDatum` 用 `[...data].reverse().find(d => d.value > 0)`，于是图例显示最后一个非零值、图表画俯冲，两者不一致——而这正是 metric-semantics 明令禁止的（"Trend charts, selected-point readouts... must use the same sampled datum"）。

## 3. 一次被实测推翻的「压倒性共识」

4 提案 × 3 评审的设计盘里，**三个提案独立收敛到同一个 Go 修复**：对「窗口边界仍未结束的 span」不发 `-1`。实测：

```
真实 live 形状（最后事件在 5s~8min 前）
  修复前          last three: [19 19 0]
  「去掉 clamp」   last three: [19 19 0]   ← 没有任何变化
  真正跨越 now 的 span：0 / 19
```

**不成立。** 会话 span 的 End 取自最后一条 transcript 事件，永远早于 now，所以不存在要抑制的 `-1`。三家的测试都能过，因为用例是照着「span 会延伸到 now」这个错误假设构造的。记入 **OPINIONS D-016**。

3 个评审独立把 minimal 排第一（108 / 80.5 / 79 / 64.5），其中 contract 评审自己跑 probe 复现了同一结论。

## 4. 实际落地

### 4.1 Go：观测瞬间不采样（metrics.go）

末点坐落在 `now`，而任何 span 都无法覆盖这一瞬间 —— 报 0 不是「当时没东西在跑」，是「这里测不到」。改为**不声明值**：

```go
if index == len(pointsAt)-1 {
    window.Points = append(window.Points, point)
    continue
}
```

`Has*` 为 false ⇒ `MarshalJSON` 直接省略字段 ⇒ TS 语义层返回 null ⇒ `chartData` 把 domain.to 画成 whitespace。**全链路已有的诚实缺失路径，不新增分支。**

代价：右缘最多滞后一个 bucket（1D 30min，30D 12h）。「现在多少」改由 hero 读 `snapshot.current` 回答 —— 另一个被正确标注的证据家族。

### 4.2 UI

- **hero 取代三按钮图例**：三个按钮只是把图表里的数字又念了一遍。改为 `snapshot.current` 的活跃会话大字 + 已知会话/可见 PID/今日峰值，并把**每个工具的 PID 分解常驻显示**（codex 23 / claude 16 / grok 6）—— 这份数据本来就在每个 runtime 采样里，此前藏在点击之后。
- **拆 y 轴**：pids 移到 `left` scale。实测 7D pids 28–106 而 burst 0–10，共享轴时最平的序列占满了轴、最有信息的被压到底部十分之一。
- **阶梯线**：三条序列 `LineType.Curved` → `WithSteps`。并发是阶梯函数，曲线画出的是从未被测量的中间值。
- **删除**：`TrendRuntimeDrilldown` 及其 4 个辅助函数（110 行）、`trendSelectedReadoutParts`（早已是死代码）、reverse-find hack、126 行 drilldown CSS、全部 legend CSS、6 个变为孤儿的 i18n key。
- **取消 430px 下隐藏 tooltip 时间戳**：那是「三个数字来自三个不同瞬间」的唯一披露，而 430px 正是 popover 宽度。

### 4.3 未采纳

多 pane 拆分（density/honesty）：需要重写 selection bead 的逐 pane 坐标计算，而两条隐形 y 轴已解决压扁问题。评审也认为两轴的歧义「不致命」。留作后续升级路径。

## 6. 有意变更的既有断言

`TestBuildTranscriptTrendWindowsUsesEvidenceAtConfiguredSourceStart`：`== len(Points)` → `== len(Points)-1`。该断言的本意是覆盖度（证据从 source start 起就齐全），末点豁免是本轮**有意新增**的语义，已在断言处注释指向新测试。

新增 `TestBuildTranscriptTrendWindowsLeavesObservationInstantUnsampled`：19 个真实形状的 live span（End 均早于 now），断言每个 range 的末点 unsampled 且**前一个 bucket 仍报 19** —— 后半句是防止「用留空掩盖真的没数据」。
