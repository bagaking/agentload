# M06_S02 · 自动化面：CLI、本地事件 API、exec-on-event

## OKR

- **Objective**：agentload 从"一个 app"升为"一个本地观测源"——脚本、statusline、tmux、用户自建 relay 都能消费它，而它自身保持零非 loopback 监听。
- KR1：演示测试：外部脚本经 SSE 消费一次状态转移并聚焦正确 tmux pane，全程 loopback。
- KR2：schema 版本化并附成文 breaking-change 政策；CLI JSON 输出在 CI 中对 schema 校验。
- KR3：网络审计：零非 loopback 监听器。

## Checklist

- [ ] 出货 agentload CLI companion：`status --json` 与 `sessions --json`，供脚本与 statusline 消费
- [ ] 文档化仅 loopback 的 REST + SSE endpoint：流式推送 attention 状态转移与看门狗线索，schema 版本化
- [ ] exec-on-event：规则触发时运行用户配置的本地脚本（tmux 聚焦、自定义 logger、用户自建 relay 由此可能——agentload 不出网络转发代码，离机推送的实现权和隐私责任都留给用户）
- [ ] 事件命名在有证据处经 M05_S04 钉版本映射层对齐 OTel GenAI semconv
- [ ] 发布文档与 worked example（tmux pane 聚焦脚本）

## 验收标准（量化）

1. 演示测试：外部脚本经 SSE 消费状态转移 → 聚焦正确 tmux pane，全程 loopback。
2. schema 版本化 + 成文 breaking-change 政策。
3. CLI JSON 输出在 CI 中对 schema 校验通过。
4. 网络审计：零非 loopback 监听器（隐私不变式回归，与 M05_S04 同一审计器）。
