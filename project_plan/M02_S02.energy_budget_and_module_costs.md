# M02_S02 · 自身成本预算：模块开关、成本公示、CI 性能门

## OKR

- **Objective**：agentload 自身成本可测、可关、可公示，且被 CI 结构性守住——"监控器不能自己变成资源大户"。
- KR1：空闲 CPU <1%（注明测量方法），24h 浸泡期间从未出现在 macOS "Apps Using Significant Energy" 榜。
- KR2：每个可轮询模块有 kill switch + 公示的成本说明。
- KR3：CI 性能门拦截空闲 CPU 相对基线回归 >20% 的合并。

## Checklist

- [ ] 测量逐模块成本（进程扫描、per-PID I/O 采样、system deck、transcript tailing），在 docs 与 UI 发布 Stats 式诚实成本说明
- [ ] config 层加逐模块 enable/disable 开关（人类可视的 Preferences 归宿在 M05_S02）
- [ ] 增加 CI 性能预算：空闲 CPU 与 allocations 对照 M01_S01 基线，超阈值即拒绝合并
- [ ] 回归测试锁死 30s 刷新下限、refresh_slot_id 合并、隐藏 surface 静默——对所有未来 poller 生效
- [ ] 带真实 agent 负载跑 24h 浸泡，验证不出现在 "Apps Using Significant Energy" 榜

## 验收标准（量化）

1. 空闲 CPU <1% 且方法留档；24h 浸泡零上榜。
2. 每个可轮询模块具备 kill switch 与已发布的成本说明。
3. CI 性能门实际拦截 >20% 空闲 CPU 回归（构造回归样例验证门有效）。
4. 刷新下限与 slot 合并回归测试绿。
