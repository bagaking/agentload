# M05_S03 · 即时 popover：预热、零闪、焦点礼仪

## OKR

- **Objective**：popover 的打开体验与原生 NSMenu 不可分辨——即时、零闪、不抢焦点，且每个 macOS 版本发布都有回归清单守着。
- KR1：热打开 ≤150ms 首绘、亮暗双主题零可见闪烁（记录在案的测量）。
- KR2：打开与关闭全程焦点不离开用户前台 app（清单逐项验证）。
- KR3：预热视图内存成本记录在案且在能耗预算内。

## Checklist

- [ ] 应用启动时在 M01_S03 快路径 bundle 上预热 WKWebView；panel 背景色亮暗双主题匹配 dashboard 主题（无白闪）
- [ ] 绝不激活应用或从用户前台窗口抢焦点；Esc 与外点关闭；验证他 app 全屏时的行为（NSPanel 退路场景）
- [ ] contentSize 钉死，防 web 内容溢出被静默裁切
- [ ] 建立按 macOS 版本的 QA 清单：JS-bridge/窗口层回归类（macOS 26.2 evaluateJavaScript ~3s 回归即此类活样本）
- [ ] 文档化退路方案：若预热无法可靠达标，glance 摘要转全原生，React 只留浏览器 dashboard（决策记入 OPINIONS_001）

## 验收标准（量化）

1. 热打开 ≤150ms 首绘，亮暗双主题零可见闪烁（测量记录在案，方法同 M01_S01 基线）。
2. 打开/关闭全程焦点不离开用户前台 app（清单逐项验证——Itsycal 被赞的"零焦点窃取"即此标准）。
3. QA 清单在当前 macOS 版本上执行并记录。
4. 预热视图内存成本记录在案且在 M02_S02 能耗预算内（WebKit ~150MB 参照系）。
