# M03_S01 · 证据驱动的会话 attention 状态

## OKR

- **Objective**：把观测转化为注意力路由的地基：每个状态可追溯到成文证据规则，push 通道快而便宜且不动扫描节奏。
- KR1：审计测试证明零无证据状态——每个发出的状态可追溯到成文规则。
- KR2：阻塞/完成夹具会话在一个事件 tick 内（<5s）浮出状态，进程扫描节奏零改动。
- KR3：事件通道空闲 CPU 增量 <0.2%（过 M02_S02 性能门）。

## Checklist

- [ ] 定义状态机：working / waiting_permission / waiting_input / finished_awaiting_review / stuck_candidate / orphaned / unknown
- [ ] **先文档后代码**：每个状态的证据规则（transcript-tail 角色+时间戳、进程存活、recent-movement 语义）写入 docs/neutral-observation-principles.md 的标准，再动手实现
- [ ] 独立包实现，只经语义层消费 adapter 证据
- [ ] 构建事件通道：transcript 文件 fsevents 触发 push 式状态转移，与 30s 进程扫描节奏架构分离
- [ ] 从覆盖矩阵为每个 vendor 附保真度标签（inferred vs 未来的 ground-truth 层级）
- [ ] snapshot API 暴露状态并附逐状态证据引文
- [ ] "unknown" 作为设计过的一等状态在三语中渲染

## 验收标准（量化）

1. 每个发出的状态可追溯到成文规则；审计测试证明零无证据状态。
2. 阻塞或完成的夹具会话在一个事件通道 tick（<5s）内浮出状态，且进程扫描节奏无任何改动。
3. 事件通道空闲 CPU 增量 <0.2%（性能门）。
4. unknown 状态 UI 经评审并完成 en/zh/ja 本地化。
