# Agent Load Trajectory Requirements

## Authority and goal

用户目标："推进 Agent load 向 traj 方向演化"，并创建 Feature Tracker，
"来彻底实现这个功能"。用户确认了 `trajectory-knowledge`（`f-22duuagpj`）的
初始实施计划，并补充要求：回溯与在线分析同构，检查漏会话和空槽，
分析自动包含 Trajectory 整形，并恢复可由会话证明的历史吞吐。执行和验收状态以 Git-ignored `.bagakit/feature-tracker/` 内
Tracker JSON 为准；本页记录需求和已采用的模型，协议见
[API Reference](api-reference.md)，人类体验见
[知识工作区](trajectory-product-scenario.md)。

Trajectory 让人和本地 Agent 找到记录过的意图、行动、回执与关联，理解观测
缺口，并回到原始证据。它提供检索、分诊与经验候选；未记录的内部推理、
实时执行状态和任务成功不能由日志外观补齐。

参考项目分析、原始出处、实验及测量材料只留在被 Git ignore 的 `.bagakit/`。
正式文档保留项目需求、接受的决策和产品契约。

## Product boundaries

- Go 单二进制，嵌入 Vite 构建；运行时不依赖 Python、脚本或远程服务。
- 仅 loopback 本地服务；观测数据不出机，不提供远程扇出、Mesh 或远程模型整理。
- Raw 证据、展示提纯、派生状态和知识记录分开；缺失保持缺失。
- 详细内容默认关闭。显式启用本地访问、当前实例凭据和配置根共同约束读取。
- 被动观察不授权重放命令、接受审批、安装 hooks、控制 Agent 或发送消息。
- 既有进程、资源、movement 和 Token 指标语义保持独立。公开 snapshot 和
  metric export 不包含轨迹正文、原文或知识标注。
- 空闲 CPU <1%；已准备好内容的原生 Popover 展开至有意义绘制 ≤150ms。
  这是产品预算，达标声明必须有真实应用测量；冷扫描、加载缺口和测量边界要明确。
  按用户要求，去掉需要人手工配合的测试门禁。当前环境不能自动完成原生开合与
  首绘计时，记录为未验证，不要求用户手工配合后才允许交付，也不能记作通过。
  可自动测量的项目继续验收；网页通过不能替代原生性能证据。

现有 [Host 门禁](privacy-local-observation.md) 是已完成基准，沿用现有实现。

## Adopted model

### Identity, event and execution

| 对象 | 含义与边界 |
| --- | --- |
| Source | 原始本地文件及物理代际；替换、截断、记录变更使旧定位失效 |
| Session | 一个来源代际中的已记录会话；跨来源关系必须有原生引用 |
| Event | 保留原生类型、ID、协议 role、actor、内容块及物理来源的观察 |
| Turn | 原生记录的执行边界；可缺失或并发，不由交替 role 或时间推断 |
| Action | 带原生 ID 的工具请求、回执、权限或输入请求 |
| Task / Run | 没有稳定的原生记录时不构造统一对象或推断目标成员关系 |

实现类型位于 `internal/snapshot/trajectory*.go`；读取、索引和派生逻辑位于
`internal/trajectory/`。公共核心不绑定某家厂商的消息布局。来源定位包含
source ID、generation、物理行、字节 offset/length、block 和 digest。
定位独立于清洗文本，原始字节可按需续读。

协议 `role=user` 不证明发送者是人。Actor 身份与 role 分离；未知身份保持未知，
不把所有未知发送者合并成一个人。Actor 查询返回有来源的参与观察，不是人员计数。

工具调用与回执只有唯一、同作用域的原生调用 ID 才配对；并发、乱序、重复 ID、
空回执和未闭合调用均可表达。未闭合调用不能单独证明现在仍在工作。

### Human–agent and agent–agent exchanges

采用共同事件核心与显式关系，不给整个 Session 设置二元对话模式。一个会话
可以包含人类更正、审批、Agent 委派、结果、同伴消息和工具传输。

关系包含 parent、reply、delegation、handoff、sent、delivered、input_inclusion、
branch_parent、resume 和 tool_result。边保留原生引用、字段路径、来源与解析状态。
只有已验证格式实际提供的边才输出；格式未提供的关系不会借用其他厂商能力。
Parent 不是 delegation；发送不是送达；送达不是模型输入包含。

关系可 resolved、missing、ambiguous、coverage_incomplete 或 unsupported。
时间邻近、共享 cwd、角色顺序和文本相似不能建立因果边。局部图可保留越窗引用；
未知目标和重复候选保持可见。

### Context indexing

| Scope | 能回答的问题 | 不能推导的结论 |
| --- | --- | --- |
| archive | 来源中记录了什么，压缩前后有哪些观察分段 | 后续模型看到了全部历史 |
| actual_input | 显式输入包含关系指向哪些记录 | 没有清单时重建完整 prompt |
| workspace | 记录的工作目录或工作区引用 | 某文件内容进入或一直保留在模型输入 |
| query_window | 当前查询/阅读选取了哪些记录 | 检索窗口就是完整因果范围 |

Context ID 绑定来源代际、scope 和原生锚点。成员可以 recorded、unknown、partial
或 complete；只有显式完整性字段及可验证成员引用支持 actual_input complete。
原生 turn ID 仅提供边界，不提供成员清单。摘要和 compaction 是转换里程碑，
保留 before/after 与来源；没有记录原始成员时 originals 保持 unknown。
分支、交付和输入可见性分别建模。

## Source and query architecture

```text
CLI / Popover / local HTTP clients
                |
       loopback HTTP JSON-RPC
                |
       typed Go trajectory service
                |
     adapters / index / raw evidence
                |
  entities / contexts / relations / attention / knowledge
```

共用服务拥有解析、身份、查询含义、证据验证和派生规则。CLI 和 UI 只投影结果，
不另做搜索、状态判定或文本归因。支持 Codex、Claude、Trae 和 Grok 的已验证
本地格式；具体覆盖见 [能力矩阵](coding-agent-evidence-adapters.md)。

索引使用已有本地 discovery/watch，完整物理行提交后才推进断点。已接受的目标
布局只持久化轻量来源目录、断点、解析状态、稀疏定位、有界候选索引和不可再生
例外；完整轨迹从来源按需重建，不把历史正文或事件数组常驻内存。该布局尚待
实现与真实全库验证。每条物理记录至多 64
块、1 MiB；单来源一次最多追加扫描 32 MiB。会话检索覆盖配置根中的历史归档，
独立于资源监控的最近 7 天窗口，不把较旧来源截在最近 512 个会话之外。
每个上限及未完成写入都有 coverage，不以丢弃伪装完整。

归档消费者启动前声明所需的完整元数据范围，最近活动、历史窗口和会话检索
共享一次目录扫描，再分别按各自时间窗口过滤。历史窗口外的文件仍属于已知
归档，不计为采样缺口。启动时先以最多 6 秒准备完整目录元数据，再发布本地
连接入口和启动短预算采样；这段准备不读正文。若目录仍不完整，保留缺口和
后续核对，不宣称全部已就绪。查询中的独立断点解码和文件身份检查使用有界并发；
所有读取完成后才继续顺序写入，不复用旧文件状态来跳过替换或缺失检查。

检索先展示命中原句，点击直接打开对应记录的前后文；会话标题和最后动作
不能代替命中内容。Context、知识笔记和关系作为进一步查看的入口。
增量索引分批准备，已准备的结果即时可读；`index_pending` 明确表示历史或
全文索引尚未完成。零命中且仍在准备时，界面显示整理进度，不声明完整无匹配。
后台在内容访问启用后自行补建，搜索页关闭不影响回溯。按来源轮转小批处理，
避免持续追加的大日志饿死旧会话；恢复完毕休眠，文件提示合并唤醒。
返回已知、解析完成、完整索引来源及事件进度。默认省略匹配总数；显式 count
才计算当前授权且准备好的投影总数，与页面条数分开。未完成索引用 pending
和进度表达，不算作被省略的数据。
普通会话/事件搜索只贡献 100ms 的整形时间片，持续追赶由后台队列负责；
仍用同一投影和断点，不为前台请求建立第二套解析。未变化的目录核对只读，
有确凿来源移除时才提交索引删除，避免每次搜索产生空写事务。
来源断点集中存放在轻量来源表，查询核对无需读取各会话的历史事件。
旧结构以有限时间片分批迁移，可中断续跑；迁移期间明确报告
`index_storage_pending`，保留原有 generation 和事件 ID，独立核验完成后切换。
会话页的命中引用一次批量读取，每会话最多 50 条，避免重复扫描全文候选。
普通词先通过有界候选索引减少来源读取，再从来源重建并验证匹配；候选索引
不作命中证据。计数、分页和引用复用同一请求中已核验记录，缓存有界并随请求释放。
按已确认的新查询契约，默认会话搜索只扫描有序候选，直到得到足够的已核验
命中及下一页 lookahead，返回当前页会话已核验的命中原句与定位，完整命中数留空；已核验记录直接复用。
默认事件搜索同样分页核验到 lookahead，无文字列表也默认省略 `matched_total`。
只有显式 count 才对授权且已准备范围逐来源完成存在性核验并给出精确总数；
页内命中和原文引用始终保持精确。`matched_count` 仅在完整计数后返回整数；默认筛选页返回 `null`，不把已展示的引用数量当作完整数。
同一来源的存在性核验由一个工作线程负责，避免并行重复读取正文；页内完整
核验和事件查询仍有界并行处理。来源身份及记录先验证，再通过共同 Decoder
重建搜索投影，保持 UTF-8、字段边界和异常字节语义。
查询取消后必须关闭全部游标和工作连接，释放读锁，保证随后写入和查询仍可完成。
短词和候选索引无法完整表示的内容仍须精确匹配；无法安全排除的候选进入有界
来源核验，不能因索引未表示而漏报。前台每次最多提交一个 256 KiB 的索引批次；
首次打开已有来源索引只读核对，避免无变化的初始化写入。失效代际和移除来源
先退出查询、匹配计数和详情访问，再由后台有界清理派生记录、配对和未引用维度。
逻辑回收不承诺 SQLite 文件立即缩小。内容访问关闭时禁止内容读取并清除内存内容；
私有磁盘中的不可再生例外、恢复状态、独立标注及非派生历史保留，不能把撤销
读取权限等同于删除有用数据。

回溯和在线追加共用 adapter Decoder、样板剥离、事件归一化、实体提取及来源
代际规则。启动时对账，文件变化触发增量检查，每 15 分钟通过既有 discovery
重新核对配置目录；补发现遗漏会话和完整记录断点后的区间。半行等待追加，
不推进断点；格式未知、缺时间、记录已丢失等空槽保留 coverage 缺口，不能补零
或拼造事件。知识候选与验证仍独立于这层整形。

原生 usage 的历史恢复共享目录发现和计数规则，但不消费提纯正文或知识推断。
恢复使用记录时间和原生 token 数，保持分钟事实、项目分区和 partial 下界；
启动不重放为当前 TPS 峰值。CPU、RSS 及会话中不存在的测量无法回填。
详细规则见 [指标语义](agent-load-metric-semantics.md)。

私有事务性索引记录重建所需的来源身份、稀疏定位、解析与恢复状态、候选摘要和
不可再生例外，不再要求永久持久化全部 normalized DTO、正文或每事件全文成员。
原文、身份配对、Context 与关系仍通过来源及共同语义服务核验；按需重建不能
只返回原始一行冒充完整轨迹。关闭内容访问立即停止读取并关闭内容数据库；
不可再生例外、恢复状态和独立标注保留，关闭期间均不可通过 API 读取。

缓存版本升级幂等重建派生投影，保留未变化来源的物理 generation 与事件 ID。
语义投影变更重建派生缓存；无损的物理格式升级分批迁移，保留既有身份和断点。批量回溯与
索引写入保留至少 1 GiB 可用磁盘空间；不足时暂停，保留提交断点并明确提示。
后台每 5 秒检查恢复条件，空间恢复后继续，不要求重新运行查询或修改访问授权。
查询修订和游标随投影版本更新。移除根立即退出查询范围；关闭内容访问清除
内存内容和游标，但保留磁盘中的身份、断点及不可再生事实。
显式写入的私有标注独立保留，关闭期间不可读取，只有显式删除才删除笔记。

索引跟随当前授权的来源文件，不作为会话备份。当前来源身份包含厂商与路径：
搬到仍被扫描的位置会按新路径重新索引，旧事件链接不自动接到新位置；搬出扫描
范围或删除文件，完整目录确认来源消失后撤回其查询投影，旧引用返回 not found。
不完整扫描不能作为删除证据，保留恢复状态并报告覆盖缺口。同路径替换或截断
建立新代际，旧引用返回 stale，不将旧引用指向新内容。来源撤回不删除独立标注、
已记录的历史或 usage；标注的来源缺失必须可见。派生页释放后可复用，文件容量
不保证立即缩小。路径搬运后的身份延续目前尚未实现。

同一历史路径只能由一个应用进程拥有，安装版与开发版不能同时写入同一数据。
进程启动前取得系统级独占锁，正常退出或崩溃后自动释放；不同的独立历史路径
可用于隔离验收。存储空间分别核算来源目录/断点、稀疏定位、候选索引、不可再生
例外和吞吐回溯索引；待迁移旧布局另列，不将其结构沿用为新布局要求。
现有指标历史的月度 gzip 归档不代表 Trajectory 已压缩。轨迹存储压缩和体积
控制须保留证据、来源代际、事件身份、标注及恢复断点。

### Storage and maintenance

用户要求：“所有 session 和其他有用文件绝对不能清理”，并要求把热力图定位的
存储放大全部优化。目标是减少索引的重复表示和页面成本，同时保留完整检索、
证据、身份、配对、使用量、标注和恢复断点。优化不能依靠删会话、裁剪正文、
近似匹配或漏报覆盖。

用户已接受额外 Trajectory 索引百 MiB 级的目标，并允许改变原有持久化
normalized DTO、正文及每事件 FTS 的方案。这些旧结构是待迁移现状，不再是
最终存储契约。百 MiB 级尚未达成，真实全库容量与查询速度都须验证；普通查询
6 秒预算也是验收目标，不能写成当前已证明的成果。原始 sessions、历史、usage
与用户标注不计入新增索引预算，绝不通过清理它们达标。容量结论须注明来源规模、
覆盖及准备状态，分别报告终态容量、实际分配和迁移峰值；分析与测量留在 `.bagakit/`。
查询可用或空间保护正常暂停，不证明已完成追赶和后续增长验收。

- 目标布局持久化轻量来源目录、generation、断点、解析状态、稀疏记录定位和
  有界候选索引；完整 Trajectory 通过同一 adapter/语义服务从源文件按需重建。
  重建覆盖内容块、事件、配对、关系、Context、实体和 coverage，不能以读取
  原始一行代替完整语义。按需读取及缓存有界，不建立另一套搜索或解析含义。
  同一来源的查询操作复用一次校验过的只读文件描述符。普通稀疏范围可以读入
  有界的不可变字节快照，先核验完整范围摘要，再从该快照重建；大于内存预算
  的遗漏记录继续流式核验。结果发布前仍检查取消、文件身份、大小、mtime 和
  当前路径；减少重复系统调用不能省略来源一致性或完整事实校验。
  实体提取可先检查各识别规则必需的字面字符，再执行原有正则；筛选只跳过
  不可能命中的规则，不改变 occurrence、覆盖缺口、排序或截断边界。
  来源尚无整体验证封印时，候选排除必须先核验该物理范围的全部原文摘要；
  核验成功才可跳过该范围的语义重建。局部核验不能冒充全来源已完成审计。
  独立会话的命中定位采用最多四个并发读取，按原有会话顺序消费结果；默认页
  找到经过核验的下一页见证后取消剩余读取，并等待它们退出。预读范围内、页边界
  之后的结果和错误不参与本页，取消或本页依赖的来源变化仍使请求失败。
  默认命中页不必整形命中原句之后的所有事件：普通范围先完整校验不可变原文
  快照，再用同一 adapter 定位第一个 canonical 命中。存在不可再生例外的范围和
  超过快照预算的范围仍执行完整重建；精确计数仍验证全部事实和范围统计。
- 公开事件 ID、source generation 与来源定位在无损迁移中保持稳定。Context
  scope、成员及转换关系、配对账本、关系解析状态、来源覆盖、显式空值以及
  字段缺失的区别必须保留。实体多条件仍必须命中同一 occurrence；标签、literal、
  scope、NativeField、顺序与外部 ID 不因稀疏索引丢失或合并。
- 在线整形与按需重建在同一物理行内共享已解析的原始字段，减少长正文的重复
  JSON 解码。共享只存在于本次行处理，不缓存完整历史正文；原始字段定位、
  空值、错误与省略语义保持一致，查询仍执行相同的来源最终校验。
- 可由授权源文件可靠再生的冗余表示可以移除；无法可靠再生的事实或恢复状态
  作为显式例外保留，并计入新布局核算。来源缺失、改写或格式变化不能伪装为
  成功重建，也不能用当前内容覆盖旧身份；无法无损核验的来源阻止迁移切换。
- 候选索引只减少读取，不证明匹配。最终命中从重建后的精确搜索投影核验，
  保持大小写、字段边界、短词、Unicode、NUL 和符号语义。无法安全排除的候选
  必须核验，不引入漏报；具体候选索引编码须经容量与速度验证，未在此锁死。
  默认返回准确页与已验证的命中原句、定位；筛选会话的 matched_count 为 null，
  不因逐会话全文计数阻塞返回。显式 count 才计算页内会话的精确匹配数和授权
  且已准备范围内总数，未准备范围仍报告缺口。
- 实体、Context、协作关系、Attention 与普通查询使用同一读取提交规则。
  扫描回调只能累计暂存结果；来源最终核验失败或请求取消时丢弃这些结果并返回
  错误，不能降为覆盖缺口后成功返回已累计内容。有界展示主动停止扫描仍须先
  完成来源核验；正常的语义缺失继续由 coverage 表达。
- 来源换代先撤回旧代际的可见性，旧事件不能继承新 generation。完整目录才
  可证明来源消失；不完整扫描不能删除缓存。派生数据与关联引用有界回收，
  不留下指向已释放记录的配对；源文件、历史、usage 和标注不参与容量清理。
  读取目录缓存时若发现文件已不存在，本轮仍报告目录不完整，并请求已有的
  适配器全目录核验；下一轮以完整发现结果确认移动或删除，不能永久重试缓存
  中的旧路径，也不能仅凭一次 stat 失败宣布来源消失。离线维护同样适用，
  不依赖文件监听器。目录恢复完整不代表缺失的原文已恢复；迁移前保护清单
  保持原样，无法核对的来源仍须报告，不能通过刷新清单掩盖损失。
  用户明确要求在外部来源已消失的情况下切换时，保留原库中该来源的全部
  事实与恢复状态为独立例外，经逐事实无损核验后允许切换；该例外不作为
  当前可读来源参与查询，不冒充原始 JSONL 备份。终验保留完整保护清单，
  单独绑定用户决定、已发现的缺失路径、旧前缀摘要和对应事实数；其余源文件、
  history、usage 和标注仍逐前缀核验，不能把新出现的缺失自动列入例外。
- 用户授权以“蚂蚁搬家”方式自动、幂等、可恢复地分批迁移：只创建一份小影子
  库，按来源或小批复制必要事实与例外、独立核验，并持久提交复制和核验断点。
  迁移期间原库不接受新增写入；失败、中断或取消保留原库与已提交进度，可续跑。
  所有来源、逻辑身份、配对/关系、Context/实体语义、coverage、恢复状态和搜索
  准备边界核验后才原子切换，随后释放旧布局，不保留长期双后端或读取 fallback。
  已核验有效前缀可以保留准备状态，落后或失效部分保留恢复记录；重启不能仅凭
  ready 标记发布，须重新确认核验条件和来源身份。
  最早的双库输入也直接读取原有物理结构，进入同一个目标布局，不先生成一份
  完整事件中间库。迁移内部可按旧格式提供只读来源目录、事实切片与恢复元数据
  读取器；正常查询及详情消费者只使用目标存储。未知字段、桶序号和原始断点
  保留为恢复证据，不将旧搜索缓存或数据库路径当作当前授权。
  被直接迁移替代的整库事件中间迁移路径退役。验收继续覆盖完整事实、公开 ID、
  Raw、配对、陈旧前缀、损坏、取消和断点恢复；按需重建不沿用旧存储的零解码假设。
  生成切换封印及发布前再次核对可再生来源的当前授权、文件身份、大小与 mtime；
  变化则回到同一影子库的分批来源核验，不能退休仍承担恢复责任的原库。
  发布后但原库尚未退休的崩溃恢复也执行同一核验；变化时将目标退回原影子位置，
  保留原 canonical 并继续分批重建。双库先退休可再生搜索库，最后退休 canonical；
  逐文件退休意图与完成状态持久化，已退休搜索库的断点只能从核验过的恢复元数据读取。
  配对迁移通过一次事件顺序遍历核验，每个 call 最多暂存两条请求和两条回执引用；
  证明状态与批次游标同事务提交，核验后移除。空间预算包含编码后的路径、桶序号、
  值、索引键和回滚日志；空值或深层路径不能绕过预算。
- 分批处理不等于每批都物理腾出空间。若 SQLite 不能安全逐批缩文件，旧文件
  直到最终核验、原子切换后才回收；不能提前删除旧库或未核验数据来给下一批
  腾空间。小影子库是目标布局，大小仍需测量，不能假定迁移中可忽略其增长。
- `agentload traj compact` 是同一二进制中的离线维护入口，先退出拥有该历史的
  应用；系统独占锁拒绝并发维护。活跃库不能直接删除或 VACUUM。迁移与重整
  不能写入源 session、历史、Usage 账本或独立用户标注。
- SQLite 提交失败不能确认写入。退役失效连接回滚残留事务，从已提交断点重试；
  每个新连接都恢复 busy timeout、临时表、外键与缓存设置，删除联动不能因
  重建连接而失效。索引损坏不能通过自动删除整库伪装恢复。
- 峰值预算包括旧库、唯一小影子库、临时/验证数据、回滚日志和 VM/swap 余量。
  普通增量与每批迁移沿用至少 1 GiB 可用磁盘保护；不足时安全暂停，保留原库
  和断点。不并行生成多份整库副本，不靠耗尽系统余量验证目标容量。
- 空间与性能验收绑定同一精确安装候选。分别记录布局各项的实际分配、峰值空间、
  停机积压、追赶完成 checkpoint、之后的实际增量，以及真实冷/暖 query、CLI/RPC
  命中身份和可读 raw。样本收益不是整库终态容量，样本速度不能替代真实查询预算。
  已完成的整库迁移与完整性核验保留原候选、输入及回执摘要。后续只有查询或
  watch 的读取改动时，可通过精确代码差异审阅和同一数据谱系复用历史存储证明；
  布局、持久写入、迁移、编码、事务边界或提交规则、容量或核验规则发生变化时必须重新核验。
  SQL、提交位置和持久结构不变的取消绑定，可复用已有库的物理证明；新增取消行为
  仍须当前夹具验证，不以历史证明替代。
  当前安装候选仍须通过全量 Go 测试、两种查询词各自的冷暖 CLI/RPC、raw 和
  追赶后的实际增长验收，不能用历史候选的查询或性能结果替代。
  终验工具只读检查实际目标库的版本、表结构、来源数量与迁移完成断点，并消费
  绑定当前代码和二进制的维护、查询、保护文件及容量记录。维护退出成功和最终
  ready 记录须与库中事件数一致；旧结构退役、百 MiB 容量及 300 秒增长窗口各自
  需要实际证据。回执缺失、候选不同或来源保护对账不全时明确失败，不生成通过
  回执，也不借验收之名修改数据库或补做一次整库迁移。
  离线维护在切换前输出独立核验完成的目标摘要、输入身份和来源数，完成后输出
  最终目标摘要；采集器将这些记录与实际生产路径、文件身份及迁移前完整清单绑定。
  查询原文按定位与真实来源字节对账；保护清单逐文件比较旧前缀，容量及增长使用
  同候选、同数据谱系和实际时间窗口内的记录，不能仅比较手填摘要。实测闲置窗口
  可以是零增量。验收读取同一份封存字节进行摘要校验与解析，不二次读取后再拼接结论。
  窗口记录保留只读查询实际得到的来源断点清单及命令输出；派生计数和断点摘要由
  验收工具从这些记录重新计算。迁移前保护清单包含完整来源文件目录，不能以目标库
  当前仍能找到的来源替代原始目录。
  追赶完成以同窗口内 Go 服务返回的实际来源准备状态为准，不能把已保存断点的
  complete 标记当成原文已经没有新尾部。终验对稳定终态文件重新计算摘要，核对
  最后一帧实际目标；容量字段逐项与封存测量对账。
  本机签名改变可执行文件摘要时，保留实际构建输出和签名前后摘要的链路；不能
  把签名后的二进制直接记为原构建输出。长会话预算记录绑定实际测试的当前输入。
  新建来源索引使用固定 16 KiB SQLite 页，减少候选过滤器和定位锚点组成的行在
  小页中的空隙；表、字段、过滤语义及公开身份保持原样。选择依据是实际来源样本
  的逐表逐值核对和分配测量，整库容量仍另行验收。SQLite 自行读取既有页格式，
  应用不增加自定义兼容层，也不对已有库直接 VACUUM。每批写入额外计入有界
  64 条记录可能触及的页与回滚日志空间，至少 1 GiB 剩余空间底线保持不变。
  迁移中来源失效后清理其未完成的影子表示，也按最多 64 行分批进行，并计入
  被删除旧值的回滚空间。清理不推进原事实游标；中断后依据剩余行继续，清理完成
  才重放原库保留的完整事实。未核验影子始终不可供内容查询，原库继续保留。
  来源在迁移读取或提交期间变化时，各读取边界采用同一个恢复规则：撤回该来源
  未核验的重建表示，分批保留原库完整事实，不推进尚未独立核验的事实断点。
  这也覆盖写入前的重建、事务最终来源校验及写入后的独立回读；不能因变化发生在
  不同边界而直接中止整库迁移或发布未核验内容。取消、容量不足和数据损坏仍按
  各自错误保留断点并停止，不能当作普通来源变化处理。
  最终复核发现已完成的来源后来被追加、替换、移走或撤回授权时，只修补发生变化的
  来源：保留其他来源的核验进度，分批保存该来源的原库完整事实，再返回最终复核。
  完整目录已证明不再授权重建的来源先进入该修补路径，避免每补存一个缺失来源
  都重复打开其前面的正常来源。目录候选筛选只决定修补顺序；全部修补完成后，
  发布前仍执行所有可再生来源的完整身份、前缀及当前文件核验。
  修补游标和返回位置必须持久化，中断后仍使用同一份影子库；不能为少数活跃会话
  重新解析整库。切换前后仍保留来源最终复核，数据损坏或取消不能触发这条修补路径。
  已封印的目标在任何修补写入前先核对旧封印；不能借合法的来源变化重新封印其他
  已损坏内容。来源目录暂未准备好时只暂停，保留目标封印与全部已核验游标。
  重建回调的逻辑字节数取规范化后公开事件的实际 JSON 编码长度；不能使用规范化前
  第一次编码的长度，造成完整事件一致但回读误报来源变化。读取预算和完整性核对
  使用同一字节定义，原文、事件身份与 DTO 含义保持不变。
  在线创建和追加范围也按同一规范化事件编码计量，不能只修迁移回读而让在线写入
  再次产生尺寸不一致。

  持久文件身份使用卷的持久 UUID 与 inode；挂载时的设备编号只参与本次读取的
  FD/路径一致性检查，不能因系统重启后编号改变而重建整库。卷 UUID 不可读时
  保留断点并报告缺口，不降级为仅路径、inode 或大小/mtime 的身份。
  旧断点升级保留公开 generation 与原始 checkpoint 字节；已复制范围须重新
  核对完整原始字节摘要，尚未复制范围继续逐事实对账，核验完成才发布新身份。
  真实 inode 替换仍按来源变化保留原事实，不能归并为设备编号变化。
  迁移的原始输入标识也是恢复记录的命名空间，绑定新物理身份时保持原值。
  新迁移另存持久输入身份与完整原库 SHA-256。旧断点缺少该摘要且物理标识已
  变化时，离线维护必须核对此前记录的完整原库摘要；没有证据就暂停并保留
  原库与唯一影子。恢复和切换仍核验原库，不能只凭 inode 相同继续退休旧库。

- 前台准备的时间片耗尽只表示索引仍待准备，不表示来源不可读；保留此前已提交的
  来源前缀与 watch 边界。后台提交新的轨迹前缀后通知同一 watch，使等待者继续读取，
  不依赖第二次文件变化，也不增加空闲轮询。测试明确准备初始基线和启用实际后台
  恢复路径；不能把一次短前台查询当作准备完成的屏障。
  搜索准备也保留已经完整核验的有界前沿：25ms 时间片决定是否启动下一批；一批
  只完整核验一个仍有新事实的块，再选择最多 256 条、256KiB 的事实前缀（首个大
  事实沿用既有上限）。已耗尽与零事实块只用于导航，不再次解码或推进事实数。
  块内读取继续服从调用方取消、校验及既有流式和逻辑大小限制；不能为赶时间提交
  半个未核验块。完成后的单次持久提交不因准备时间片在磁盘同步阶段耗尽而反复
  回滚。调用方取消仍阻止发布查询结果，容量保护和当前授权保持有效；有界工作量
  不承诺操作系统磁盘等待时长。

  迁移的目录发现不能耗尽所有批次机会：批次时间片从完整目录准备好后开始，
  调用方的取消和硬截止时间始终有效。时间片只限制是否继续下一批；即使本轮
  时间片已耗尽，也先执行一个有界、独立核验并持久提交的小批，再让出执行权。
  不能反复重扫目录而永远不推进断点。
  目录不完整、调用方取消和容量不足仍暂停，不推进未核验事实。

### Shared service and interfaces

保留四个小操作：

| 操作 | 功能 |
| --- | --- |
| `traj.query` | 按类型化条件查询 sessions、events、actors、relations、contexts、entities、knowledge、attention |
| `traj.get` | 按返回 ID 读取有界详情、过程、原文、关系或 Context 成员清单 |
| `traj.watch` | events/sessions 的有界增量读取；失去连续性时显式要求重查 |
| `traj.annotate` | 显式创建、撤回或删除本地知识记录 |

传输为 `POST /api/rpc` 的 JSON-RPC 2.0；CLI 在同一二进制中连接当前本地实例。
无需第二 daemon、Graph 数据库、逐方法 REST 副本或 stdio 服务。
现有 snapshot API 保持自己的契约。

查询不是任意执行语言。工具、Skill、实体 predicate、协议 role、actor、
来源会话、Context scope、知识 kind/state 分开。未支持的组合报错，不静默忽略。
Popover 搜索编译成同一组选择器。

普通查询至多 50 项且编码结果 ≤64 KiB；关系查询 ≤32 KiB；get ≤5 KiB。
长原生 ID 在展示投影中明确省略，不截成另一个身份；完整原文仍可通过同一
canonical locator 分块读取。Session 的 matched_count 是可空的精确匹配数：
整数表示已完整核验，null 表示尚未计数；matched_ids 是已验证的有界引用列表，
不能把引用数量当成完整命中数。无筛选目录可直接使用已知的全部事件数。

已确认的 sessions/events 查询契约：默认优先快速返回准确命中页，不为了全库
总数或逐会话全文计数阻塞返回。默认筛选 Session 的 `matched_count` 为 null；
命中原文身份与定位保持精确；
`next` 只能来自已验证的后续命中，不能根据估算或尚未检查的候选生成。
默认省略 `matched_total`（含无文字列表），其含义是未知，不是 0。

精确总数由显式计数请求获取：JSON-RPC `traj.query` 查询选择器使用
`count: true`，CLI 使用 `query sessions --count` 或 `query events --count`。
返回的 `matched_total` 是当前授权且已准备边界内、分页前的精确命中总数；
索引未追赶完成时 coverage 仍须标示不全，不能把它称为完整历史总数。
分页 cursor 绑定 count 模式，普通模式与显式计数模式不能混用游标。

普通请求维持服务端 6 秒、CLI 7 秒超时；单条显式 count 请求采用服务端 60 秒、
CLI 61 秒上限，且支持取消。JSON-RPC batch 仍共享总计 6 秒的服务端期限，
并拒绝 `count: true`，计数必须单独请求。该模式及其超时/取消行为正在实现，须通过当前
查询夹具和真实服务验收后才能宣称已验证。

分页游标与增量游标分开。Watch 复用已有文件通知，不高频轮询，返回 metadata
及来源定位而非正文；256 条内存窗口、50 条批次、10 分钟游标有效期。初次 watch、
游标过期、窗口丢失、来源代际或访问范围变化要求重新 query，再从 watch_cursor
接续。CLI NDJSON 每行是一份完整批次；通知本身不是可靠订阅。

索引准备进度的变化不代表事件观察失去连续性，不应使增量游标失效；实际来源、
代际、访问范围或观察缺口变化仍要求重查。返回的 coverage 继续如实报告准备缺口。

## Entities, knowledge and improvement consumers

用户提出从"某个名词、工具、skill"出发搜索，并将 Session 作为知识库使用。
采用确定性提取和有来源的本地标注，不默认依赖远程语义模型。

实体包括 term、tool、skill、path 和 version；predicate 区分 mention、called、
requested_read、read、requested_load、loaded。请求读取、命令提及或工具成功
不自动证明已加载 Skill。相对路径没有记录 cwd 时保持未解析作用域；同名、
不同版本、basename 或 symlink 不无依据合并。

知识 kind 为 observation、candidate、verification、counterexample；state 为
active 或 withdrawn。验证和反证是独立记录，不覆盖旧证据或自动改写候选为
“已验证通用经验”。适用 configuration、environment、version、evaluation_refs
和 artifact_refs 由明确调用提供；缺失范围保持 unprovided/partial。
外部引用只保留，不下载或执行。

自动经验候选只描述可验证的行动/回执序列。相同行动需要工具与 JSON 参数一致；
参数变化的序列需要唯一的原生关联。每条候选保留提取规则版本、来源、观察范围、
支持与可能反证。结果变化不证明因果，工具成功不证明任务完成；缺少证据时不生成。
候选来源撤回或改变后失效，显式笔记保留并显示来源缺口。

这套设施使历史轨迹自然成为证据库，减少重复手写经历的负担。可复用建议还需要
提炼、适用条件和验证。未记录的判断、配置、版本、历史产物与评测不能从 Session
自动补齐，仍可主动本地标注。

RSI 消费者可以 query/get/watch 读取证据、候选和明确提供的外部版本/评测引用。
Agent Load 不执行候选、实验、评测、优化或回放。效果归因须由外部受控比较证明。

## Attention and triage

执行进度、干预与覆盖分别输出，liveness 保持 unknown。原生审批请求只有确切
请求/响应引用才闭合；并发执行和等待权限可以共存。原始结束问句只提供 hint。
规则 `native-attention-v1`：同工具、同记录 turn 的最近 20 个工具行动内出现
3 个不同原生调用错误，形成 stuck_candidate；明确成功回执、新的记录范围或
窗口过期按公开规则解除，缺失作用域或覆盖时保持 unavailable。

旧资源 attention 不被轨迹猜测替换。私有轨迹诊断通过同一 API 提供依据，
详见 [中立观察](neutral-observation-principles.md)。

## Typical uses and acceptance

- 人类：查当前明确干预、定位失败调用、从过程回到证据、查看压缩边界、复查经验范围。
- Agent：筛选以往工具/Skill 使用，读取局部证据，接续新观察，主动补充限定经验与反证。
- 外部改进器：读取观察和评测引用，形成假设，独立验证当前环境与效果。

验收包括四厂商真实格式、并发乱序、空结果、重复/缺失 ID、半行、文件替换、
中断、branch/resume、actor-role 分离、Context 未知/完整与压缩、不相关成功、
来源撤回、跨 CLI/API/UI 同身份、访问关闭和公开导出排除。
图只按需加载，不添加无证据的因果关系；空态与覆盖缺口分开。

保留可自动执行的数据真实性、查询正确性与预算、原文身份、存储保护和恢复
验收。取消的是依赖人手工配合的测试门禁，不是这些自动验收。当前无法自动
验证的原生开合/首绘单独记录环境限制与未验证状态，不能用跳过、安装成功或
网页测试通过证明原生 ≤150ms；空闲 CPU 同样只有真实测量后才能声明达标。

未来完整 prompt 采集、历史产物快照、任务级 Review Digest、受控回放、语义推理
和全量 Dashboard 图谱需要自己的证据来源及范围决定，不列为当前已具备能力。
