# M01_S03 · main.tsx 模块拆分与 popover 快速路径

## OKR

- **Objective**：popover 关键路径的 JS 载荷显著瘦身，首绘接近原生 glance 体验，且刷新纪律零回归。
- KR1：popover 关键路径 JS 载荷较 M01_S01 基线减少 ≥30%。
- KR2：基线硬件上热 popover 首绘 ≤150ms（或记录差距 + 后续方案）。
- KR3：隐藏 surface 零 snapshot 请求，有回归测试锁定。

## Checklist

- [x] main.tsx 的重型模块已拆为模块级 chunk：trend suite、diagnostics、system deck 均通过 `React.lazy` 加载；dashboard shell 保留同步以避免导航壳闪烁
- [x] popover 关键路径排除 trend/diagnostics/system deck bundle；当前构建产物会单独生成三个模块 chunk
- [ ] 拆分后保留 visibility-aware 轮询、refresh_slot_id 合并、ETag/If-None-Match 缓存，并配回归测试
- [ ] bundle 结构面向 WKWebView 预热设计（M05_S03 消费）
- [ ] 在新 chunk 布局上重建嵌入的 ui/dist，并复跑 locale 校验器
- [ ] 对照 M01_S01 基线重测 popover 首绘

## 落地记录（2026-09-22）

- `ui/src/main.tsx` 不再静态引入 `SystemResourceDeck`；构建产物出现独立 `SystemResourceDeck-*.js`，初始入口从约 404 kB 降到约 393 kB（gzip 约 118 kB → 115 kB）。Trend 与 Diagnostics 原有懒加载保持不变。
- popover 的 attention strip 放在在线证据面最前方；它消费后端 `attention_state`，不在 UI 重新推断 stale/idle 语义。
- 首绘的 150ms 仍需在基线硬件上做原生窗口实测；未测量前不把 bundle 缩减写成首绘承诺。

## 验收标准（量化）

1. popover 关键路径 JS 载荷较基线 ≥30% 缩减。
2. 热 popover 首绘 ≤150ms（基线硬件），或在仓库文档记录差距与跟进计划。
3. 隐藏 surface 零 snapshot 请求（回归测试证明）。
4. 四道质量门全绿，含新布局上的 locale parity。
