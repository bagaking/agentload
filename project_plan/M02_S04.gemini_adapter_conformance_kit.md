# M02_S04 · Vendor 第一波 b：gemini-cli adapter 与 conformance 套件

## OKR

- **Objective**：第二个新 vendor 验证抽象可复制，并把接入标准固化为 CI 套件 + 可执行 playbook，使未来贡献者（包括 AI agent）能独立加 vendor。
- KR1：gemini-cli 在其格式允许处达到证据对等，其余 cell 诚实分级标注。
- KR2：conformance 套件在 CI 覆盖全部五个 adapter；蓄意破坏的夹具能使其失败。
- KR3：五个活跃 adapter 下性能门保持绿——空闲 CPU 零回归。

## Checklist

- [ ] 按同一标准构建 gemini-cli adapter：transcript 根、env fallback、golden 夹具、诚实矩阵层级
- [ ] 抽出 adapter conformance 套件：夹具 harness + 能力声明检查，全部现有与未来 adapter 在 CI 必过
- [ ] 从套件生成"adding a vendor"playbook，面向未来贡献者与 AI agent
- [ ] 五个活跃 vendor adapter 下复跑性能门
- [ ] 对照 M02_S03 基准确认 ≤1 周/vendor；若抽象失败，在继续任何广度扩张前先修抽象（必要时开 Mini-Sprint）

## 验收标准（量化）

1. gemini-cli 在格式允许处证据对等，其余位置分级标注。
2. conformance 套件在 CI 跑全部五个 adapter；一个蓄意破坏的夹具使其失败（套件有效性证明）。
3. vendor playbook 端到端验证：按文档操作不触碰任何 core 包。
4. 五 adapter 下性能门绿——空闲 CPU 无回归。
