## 计划偏差：七包目标不成立（2026-09-20，实测驳回）

原 checklist 要求拆成七个包。**依据 Go 的语言规则与本仓库的实际引用图，这个形状物理上做不到**，逐条核实如下：

| 环 | 事实 | 后果 |
|---|---|---|
| E | `trayApp` 有 61 个方法，42 个在 `tray.go`、19 个在 `server.go` | Go 要求一个类型的所有方法在该类型自己的包内 → **server 与 tray 不可能是两个包** |
| D | `Observer` / `codingAgentRegistry` / `transcriptEvidenceIndex` 互为字段 | 三者必须同包 |
| A | `history.go:452` 用 `defaultTrendSpecs`（metrics.go）；`metrics.go:510` 收 `ThroughputMinuteFact`（throughput_history.go） | history ↔ metrics 双向 |
| B | `observer.go` 调 `metricFactsForLiveSession`（metric_semantics.go），该函数收 `liveSessionObservation`（observer.go:1262） | observer ↔ semantics 双向 |
| C | metrics / semantics / live_token_rate 围绕 `liveTokenRateEvent` 与状态常量熔在一起 | 三者同包 |

另有两条与包划分无关、但会否掉"把 server.go 搬走"的物理约束：

- `//go:embed ui/dist/*` **不能引用父目录**，所以持有 embed 的文件必须留在仓库根。
- `native_popover_darwin.m/.h` 用裸 `#include`，而 cgo 只编译**导入包自身目录**下的 `.m`/`.c` —— Go 桥接与 ObjC 文件必须同进同出。

**诚实的结构是 4–5 包**：`internal/snapshot`（叶子，已落地）、`agents`（vendor adapter 群）、`core`（observer + transcripts + metrics + history，即上面 A–D 四个环的并集）、`app`（server + tray + native，受 embed 与 cgo 约束留在根）。`types.go` 原本不在七包清单里，却是**唯一必须先拆的那个**——它被所有包同时生产和消费，留在任何行为包里都会让其余三个互相 import。

判据：`go list -deps ./internal/snapshot` 只输出它自己。

## 落地记录（2026-09-20）

**第一块：`internal/snapshot`（commit `efbc0ce`）**

- 42 个文件、59 个类型名限定，wire 格式零变化——`TestSnapshotMatchesGolden` **未重新生成即通过**，这正是该夹具存在的理由。
- 跟着类型一起搬的四样东西（属于"类型是什么"而非"observer 做什么"）：`TokenUsage` 的 Empty/DerivedTotal/Add/Max、`maxInt`、`CloneLiveTokenRateProjectSamples`（包内 `TrendPoint.MarshalJSON` 与包外 live/history 都要，故导出）。反向搬出的一样：`transcriptCacheState` 进 `transcripts.go`，因为除扫描路径外无人读。

- **机械性自检**：把"限定符"与 `snapshot`→`snap`/`cached`/`fresh` 重命名归一化后比对 diff，幸存 74 行——全部是 import、上述四处搬移、以及 server.go 里三个手工改名的局部变量。

**KR2 实际形状（commit `8cb2740`）**

守卫盯的是**词汇**而不是算术。盯算术（`/`、`* 100`）会把仓库里每个字节计算和排序比较都标红，一周内必被关掉；而一个指标词出现在定义它的文件之外，既罕见又永远值得看一眼。

- 新增 freshness 常量 + 唯一分类器 `freshnessFromEventAge` + 两个谓词，observer 的五处内联全部改走语义层。
- **首次运行就抓到一个真问题，因此没有豁免它**：`recentMovementStatus` 返回的 `"idle"` 属于 baseline-status 族，与 freshness 族只差一个词却不是一回事——全机会话皆 stale 时 baseline 报 idle，而没有任何一个会话是 freshnessIdle。已改名 `baselineStatusIdle`，**并刻意声明在 `freshnessIdle` 旁边**，让差异出现在同一屏而不是两个永远不会一起读的文件里。
- 变异验证：把 `observer.go:2085` 改回裸 `"stale"` → 守卫变红并打印行号；改回 → 绿。

**KR3 实际形状（commit `8cb2740`）**

stub 本身就是测试文件：一个虚构 agent 的完整 adapter，四个能力槽全填，配三个**测量而非断言**的测试。

- **实测 130 行 / 预算 200 行**。
- 端到端跑通：播种 transcript → registry 走查 → 解析出 2 事件 42 output tokens → usage decoder → 能力矩阵。**预算若是量在一段解析不了任何东西的代码上，就什么都没量到。**
- 局部性测试：stub 的 id 出现在任何其他文件里即失败——需要在 `observer.go` 散落改动的 vendor 不是变便宜了，只是看起来便宜。
- 预算被突破时，失败信息要求**回 sprint 重新协商**，而不是就地抬高数字。
