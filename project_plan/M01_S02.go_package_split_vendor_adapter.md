# M01_S02 · Go 包拆分与 VendorAdapter 抽象

## OKR

- **Objective**：三个既有 vendor 全部跑在 adapter 抽象上且行为零漂移，新 vendor 的接入成本被结构性压低。
- KR1：golden snapshot 夹具在重构前后 byte 级一致（零 diff）。
- KR2：语义层守卫进 CI——metrics/semantics 包之外出现指标运算即失败。
- KR3：编译级 stub adapter 证明新增 vendor 只触碰自己的包、<200 LOC。

## Checklist

- [ ] 扁平根包拆为有边界的包：observer/process、transcripts、history、metrics/semantics、server、native shell/tray、config
- [ ] 定义 VendorAdapter 接口：进程分类、transcript 根目录 + 工具原生 env fallback、会话/角色解析、token 提取
- [ ] 每个 adapter 附能力声明（capability declaration），枚举其可产出的证据族——M02_S01 覆盖矩阵将由此生成
- [ ] claude、codex、trae 移植到 adapter，保留 CLAUDE_CONFIG_DIR / CODEX_HOME / TRAE_CLI_HOME fallback
- [ ] 增加 golden snapshot 测试，使 /api/snapshot 在重构前后可 byte 级比对
- [ ] 增加 lint/测试守卫：禁止 semantics 包之外的指标运算（落实仓库既有约束）

## 验收标准（量化）

1. 三个既有 vendor 全部经 adapter 运行，golden snapshot 夹具零 diff。
2. 语义层守卫由 CI 强制：除 metrics/semantics 外无任何包计算指标。
3. 新布局下 `go test ./...` 绿，adapter 包覆盖率不低于拆分前平均值。
4. 一个 compile-only stub vendor adapter 证明：新增 vendor 仅触碰自身包、<200 LOC。
