# M04_S02 · 配额窗口观测与诚实 unknown

## OKR

- **Objective**：在唯一可辩护的立场上服务配额焦虑——显示观测证据、明确标注未知，成为品类里第一个厂商改限额也不"说谎"的监控器。
- KR1：审计测试证明零个非用户自报的限额值被渲染。
- KR2：窗口燃烧位置与 fixture transcript 完全一致；unknown 窗口渲染为设计过的空状态。
- KR3：厂商改计划的 fixture 场景下显示保持真实（anti-"misleading monitor" 门）。

## Checklist

- [ ] 从 transcript 证据把观测 token 燃烧聚合进厂商成文的窗口形状（5h / weekly）
- [ ] 重置时间戳只在厂商本地写下时读取（Codex CLI 有写）；否则渲染"unknown——厂商不公开账本"
- [ ] 支持可选的用户自报计划限额，视觉标记 user-supplied——绝不推断、绝不众筹
- [ ] 仅在限额已自报时渲染耗尽 ETA，附显式置信标签；unknown 保持 unknown
- [ ] UI 文案言明何为证据、何为缺失；docs 中援引 OTel GenAI "must not report what cannot be obtained" 规则作标准级背书
- [ ] 为全部窗口表面补齐矩阵 cell 与 en/zh/ja 字符串

## 验收标准（量化）

1. 审计测试：零个用户未自报的限额值被渲染。
2. 窗口燃烧位置与 fixture transcript 完全一致；unknown 窗口是设计过的空状态而非空白。
3. 自报限额的 ETA 带置信标签与 user-supplied 标记，三语齐备。
4. 厂商改计划 fixture 场景：显示保持真实（品类里所有外推工具在此翻车——ccusage #298/#483、CCUM #52）。
