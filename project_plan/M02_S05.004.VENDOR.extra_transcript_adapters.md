## 3. 关键区分：代码档位 ≠ 本机语料

**这是本文件最重要的一条。** 实测本机（2026-09-19）：

| vendor | 本机语料 | 生产解析器实测 |
|---|---|---|
| **hermes** | `state.db` 536MB | **10287 个 session trace，1932 个含 output token** ✅ |
| gemini | 1 个 session 文件 | `trace=nil` —— 该文件是 `{kind, $set, content, id}` 形态，无 token、无 role |
| openclaw | **0** 个 jsonl（只有 `skills/`） | 无输入 |
| pi | **0** 个 jsonl（只有 `agent/extensions`、`agent/skills`） | 无输入 |
| opencode | 根目录不存在 | 无输入 |

**四家出不了数是正确行为，不是缺陷。** 解析不出证据即产出 nil，不落任何数字：

```go
if u.OutputTokens <= 0 { return liveTokenRateObservation{}, false }   // DecodeUsage
if trace == nil || len(trace.EventTimes) == 0 { return nil }          // nonEmptyTrace
```

活体快照交叉验证：`current_by_tool` 里五家均为 `pid_concurrency: 0`——这是 **`tool_coverage` 档位的真实观测 0**（其 `missing_state` 明示「zero only means no session or process evidence was observed」），而 `token_usage` / `output_token_throughput` 两条经济档指标**对这五家一个字节都没出**。「进程档的真 0」与「token 档的假 0」不是一回事。

**因此 gemini/openclaw/pi 声明 Usage 槽不违反「绝不虚构」**：声明的是「本 adapter 能解析这种格式」，不是「本机有这个数」。后者由 nil 链路如实表达为缺省。

## 6. 已知天花板（不修，记明）

- **`isAgentDatabase` 让 DB 每次扫描都重解析**（`transcripts.go:359` / `:793`），绕过 size+mtime 缓存。**理由正当**：DB 的 mtime 不反映已提交的 WAL 写入，靠 mtime 会漏数据。**代价真实**：本机 hermes 全解析一次 **6.84s**。今天不付这个钱——`state.db` 距今 9 天，在 7 天历史地平线**之外**，发现阶段即 deferred（活体快照 hermes 全 0 与此一致）。但**一个活跃的 hermes 用户会每次扫描都付**。
  `ponytail:` 若出现活跃 hermes 用户抱怨刷新变慢，升级路径是按 WAL 大小/偏移做增量游标，而非放弃重解析。
- **`sqlite3 -readonly` 直开活库**而非拷贝到 /tmp。非仓库规则违反（见 §4.3），且 read-only 不可能写坏源库；checkpoint 中途读失败会走诊断通路而非出错数。
- **文档能力矩阵手工维护**（`docs/coding-agent-evidence-adapters.md:39-44`）。矩阵门禁要求「由 adapter 代码生成」，但仓库内**不存在**该生成器（无 `go:generate`、无脚本、无 pin 测试）。已逐行核对 6 个变更行与 `agent_registry.go:139-186` 一致——**当前准确，风险是未来漂移**。属 M02_S01（Evidence Coverage Matrix 同源生成）的既有范围。
