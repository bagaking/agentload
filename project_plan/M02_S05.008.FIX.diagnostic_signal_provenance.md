## 1. 为什么有这个 mini-sprint

`M02_S05.007` 修的是「后端算了、前端丢了」。这次复查发现同一族缺陷还有三处存活，
共同形状是：**生产者写一个值，消费者按字符串字面量去接，中间没有任何东西比对两张表**。
和 D-029 一样，它们全都不报错——因为 `""` 是 `omitempty` 字段的合法值，
而 i18n 查不到 key 时会 fallback 成一个「看起来像人话」的词。

## 2. 三个缺陷（都在实机快照上复现过）

### 2.1 `diagnosticMetricForRisk` 的死分支（根因）

`observer.go:2187` 发出的 kind 是 `duplicate_overlap_candidates`，
而 `diagnostics.go` 的 switch 写的是 `duplicate_overlap`——**一个永不命中的分支**。
连带地，9 个 risk kind 里只有 2 个被映射，其余 7 个带着 `metric_key == ""` 到达前端。

实机快照（120 PID / 99 会话）实测：11 条 signal 里 **6 条没有 metric_key**。
后果有两层：证据列退化成 humanize 后的裸标识符；且它们永远无法与 evolution 卡片关联。

**修法**：按 `docs/agent-load-metric-semantics.md` 给全部 9 个 kind 指定语义族，
并注明判定理由（recent_movement 只由 transcript 事件年龄决定，所以只有真正比较事件年龄的
两个 kind 属于它；spread / overlap / peak / top-share 描述的是会话在项目与 lane 上的分布，
属于 role_matrix，不是 process_pressure）。

### 2.2 `process_observer` 三语全缺文案

`diagnostics.go` 发出 6 个 Source，`i18n.ts` 只有 5 个标签。
`diagnosticSourceLabel` 查不到就 humanize，于是中文页和日文页都显示英文 "process observer"。
这与 `M02_S05.007` 抓到的 `process_observation_incomplete` 是**同一个 signal**——
上轮补了它的 Title/Detail，漏了它的 Source 标签，因为当时的门只扫 kind 不扫 source。

### 2.3 evolution 卡片的「证据来源」指向了它没读过的数字（最严重）

`buildEvolutionRows` 用 `metric_key` 相等来做 insight 与 signal 的关联。
但 metric_key 是**语义族**，粒度远粗于出处：一个族下有多个互不相干的 signal。

实机实测后果：`session_hygiene` 卡片的数字来自 `StaleSessionCount` / `ChurnSessionCount`，
但它的「证据来源」行指向了 `low_confidence_sessions` 与 `candidate_workitem_coverage`
——**两条它从来没有读过的记录**。

这比没有出处更糟：出处行的作用就是邀请读者去核对，指错了会让读者拿一个数字去对一条
无法印证它的行。按「绝不虚构」，这是虚构了一条血缘。

**修法**：不去猜，让生产端直说。`DiagnosticEvolutionInsight` 增加 `SignalKinds`，
每个 insight 声明自己实际读的那两个计数器对应的 signal；前端按 kind 求交集。
`baseline_review` 故意不带——它是「没有任何触发」时才出现的卡片，本来就没有来源，
此时不画出处行，而不是画一条猜的。

## 3. 三道新门（都不维护清单）

| 门 | 比对的两张表 | 首跑结果 |
|---|---|---|
| `TestEveryRiskSignalKindCarriesAMetricFamily` | 正则扫 `observer.go` 的 `RiskSignalSnapshot{Kind:` × `defaultMetricRegistry()` | **首跑即红**，抓出 6 个 kind |
| `TestEveryDiagnosticSignalSourceHasLocalizedCopy` | 正则扫 `diagnostics.go` 的 `Source:` × 按 locale 块扫 `i18n.ts` | **首跑即红**，抓出 `process_observer` × 3 语 |
| `TestEvolutionInsightsNameSignalsThatExist` | insight 声明的 `SignalKinds` × 全仓实际发出的 kind | 绿；变异验证见下 |

三道门的两侧都从源码扫出来，**没有一处手写清单**——手写清单需要被它要拦截的那次改动
顺手更新，那正是它存在的意义所在的那一步。

新门同时还把语义族约束进 `defaultMetricRegistry()`：族名写错或写了个注册表里没有的族，
同样会红，因为族外的名字没有语义定义可供对照。

## 4. 验收

**变异测试**（门必须能红才算门）：把 `SignalKinds` 里的
`duplicate_overlap_candidates` 改回历史上真实出现过的笔误 `duplicate_overlap`，
`TestEvolutionInsightsNameSignalsThatExist` 如期失败并打印该 kind 无人发出；还原后转绿。
另两道门首跑即抓到真缺陷，无需注入。

**渲染层实测**（遵循 D-029：抓 API 只能证明序列化层）：
由于装机进程 `go:embed` 旧产物、且当时另一会话正在同一文件上开发 P0 损耗台账，
不便重装。改为用**真实后端函数**在实机快照上重算 diagnostics，
再用 `sucrase-node` + `renderToStaticMarkup` 渲染**真实 `DiagnosticsPanel`** 三语各一遍。
数据与组件都是真的，没有构造夹具。

```

CARD coordination_shape   traced-to: ["疑似重复或重叠会话","项目分布较散"]      +0 hidden
CARD evidence_boundary    traced-to: ["低置信会话证据","存在未映射会话的进程"]  +0 hidden
```

`session_hygiene` 的两条来源确实都被 6 行上限挤到表外，现在如实报「另有 2 条」，
而不再拿两条无关的行顶替——这正是修复前后的差别。

**四门全绿**：`scripts/quality_gate.sh`（go vet / go test / ui build / locale parity）。

## 5. 收口后自查又抓到两条（本轮最值得记的部分）

修完上面三条后跑了一次对抗审计，**抓出的第一条缺陷是我自己刚写进去的**。

### 5.1 `recent_sessions` 被我错分到 `recent_movement`

我在 §2.1 给 9 个 kind 指定语义族时，把 `sessions_without_recent_event` 和
`recent_sessions` 写进了同一个 case，注释还自陈「一个看最后事件、一个看首个事件」
——**注释已经写明了它们不是同一根轴，我却把它们归了同一族**。

核实（`observer.go:1377`、`recentSessionWindow`）：

| | 读的事件 | 窗口 |
|---|---|---|
| recent_movement | **最后**一个事件的年龄 | `idle_gap` ≈ 90s |
| `recent_sessions` | **首个**事件（会话诞生） | `idleGap*10`，钳在 15m–1h |

两个总体互斥：40 分钟前开、之后一直静默的会话算 churn 但零 movement；
几天前开、刚写了一条事件的会话是 movement 但不算 churn。
实机页面上，`1 live sessions started within the last 15m` 这一行的证据族标签
渲染成「Fresh movement / 最近动作」——**把会话诞生数挂在了最近活动语义下**，
正是 AGENTS.md 明令禁止的 mix semantic families。已改判为 `known_sessions`
（它是一个按诞生时间筛选的已知会话计数，不是事件年龄读数）。

### 5.2 同一次改名，两个 switch，我只修了一个

`diagnosticTitleForRisk` 里还有第二个 `case "duplicate_overlap"` 死分支。
我在 §2.1 修 `diagnosticMetricForRisk` 时**没有回头问「这个 kind 还被谁 switch」**。

它不影响页面（前端从 i18n 重新取文案），但 `/api/diagnostic-export` 直接发这个字符串，
且没有第二来源。实测导出里 6 个 kind 的 title 是自己标识符去掉下划线的结果，
如 `"duplicate overlap candidates"`。已为全部 9 个 kind 补上导出标题。

### 5.3 因此又加两道门

| 门 | 拦什么 | 变异验证 |
|---|---|---|
| `TestEveryRiskSignalKindHasAnExportTitle` | kind 没有导出标题（落进只去下划线的 default 臂） | 删掉一个分支 → 如期红 |
| `TestRiskSwitchesNameNoKindNobodyEmits` | 任一 risk switch 里存在无人发出的死分支 | 把 `duplicate_overlap_candidates` 改回历史笔误 → 两道门同时红 |

第二道门扫的是 `diagnosticTitleForRisk` 与 `diagnosticMetricForRisk` **两个**函数，
而不是这次出问题的那一个——这正是 5.2 的教训：加门时该问的是
「这套词汇表有几个消费者」，不是「这次的 bug 在哪个消费者」。

### 5.4 我自己的门为什么没拦住 5.1

`TestEveryRiskSignalKindCarriesAMetricFamily` 只断言「族名非空且在注册表里」，
`recent_movement` 两条都满足。**它验的是「填了没有」，不是「填对没有」。**
语义正确性没法用一条正则判定，所以这里不硬造一道假门；
判据写进 OPINIONS D-032 附带四：给指标归族时，判据必须是它**读的哪个事件、比的哪个窗口**，
不是名字读起来像什么。
