# M02_S05.007.FIX — 诊断页丢掉的证据格与它缺的那道门

## 1. 为什么有这个 mini-sprint

`M02_S05.006.RSI` 的验收写着「诊断面 `evidence_walk_cost 319ms ok`」，并且那是**真的**——我在装机后抓的是 `/api/snapshot` 与导出 JSON。

**但页面上没有。** 前端 `diagnosticModel.ts` 的 `buildEvidenceMetrics` 按字符串字面量挑三条 baseline（`active_session_ratio` / `mapping_coverage` / `token_measured_sessions`），后端 `buildDiagnosticBaselines` 产出的是**五条**。`evidence_walk_cost` 与 `low_confidence_sessions` 每次快照都算、都序列化、然后被视图模型静默丢弃。

**根因不是漏写，是没有任何东西在比对这两个列表。** 所以本 sprint 的一半是补格子，另一半是补那个比对。

**验证方法的教训（本条最值得记）**：「API 里有」不等于「页面上有」。上一轮我验证的是序列化层，声称的却是渲染层。见 OPINIONS **D-029**。

## 2. 落地内容

### 2.1 补上被丢掉的两格（`evidence_walk_cost` / `low_confidence_sessions`）

证据条从 3 格变 6 格：

| key | 值来源 | 有无百分比 |
|---|---|---|
| `session_evidence` | baseline `active_session_ratio` | 有 |
| `pid_link` | baseline `mapping_coverage` | 有 |
| `token_visible` | baseline `token_measured_sessions` | 有 |
| `low_confidence` | baseline `low_confidence_sessions` | **无**（裸计数，分母在另一格） |
| `walk_cost` | baseline `evidence_walk_cost` + `transcript_stats.scan_cost` | **无**（时长） |
| `walk_scope` | `scan_cost.visited_entries` / `pruned_directories` | **无**（计数） |

**时长/计数格绝不显示百分比条。** 原 CSS 是 `width: max(2%, var(--metric-pct))`，而 `baselinePercent("512ms")` 返回 0——会画出一条 2% 的细条。时长根本没有百分比，画条就是虚构。改法是 `percent: number | null`，null 时整条不渲染，改画一条虚线占位（保持六格基线对齐，但不冒充测量值）。

**顺手修掉同一处的上游虚构**：`baselinePercent` 对**任何**无法解析的值都返回 0，所以认不出的值也在 "n/a" 旁边画 2% 的条。返回值改为 `number | null`，根因一次修完。

**注意这个类型改造只解决了「没有分母」，没解决「分母有、分子是零」——后者是装机渲染时才抓到的，见 §4.2。**

### 2.2 扫描开销的诚实形状：值 + 测于何时

`M02_S05.006.RSI` §5.1 陷阱二说过「只报本次 pass 等于几乎永远不报」。同一条在 UI 层要再落一次：

- `walk_measured === false` → 值为 `no data`，副标「no walk measured yet」，tone muted。**唯一的空态入口。**
- `walk_measured === true && walk_fresh === false` → 出数，副标「last measured {at}」。索引约每进程 reconcile 一次，**稳态下这是常态路径**，不是异常。
- `walk_measured === true && walk_fresh === true` → 出数，副标「measured this refresh」。

值本身**直接用后端 baseline 的字符串**，不在前端重算 `elapsed_ms`——后端已经格式化并已经守住了未测量分支（`diagnostics.go` `scanCostValue`），前端再算一遍就是对同一事实的第二意见。

`walk_measured===true && elapsed_ms===0` 是**合法测量**（golden 夹具走空目录），所以 `elapsed===0` 永远不能当作「未测量」的判据。

### 2.3 `no_data` 不再以裸 token 出现在页面上

`diagnosticBaselineValue` 原本对认不出的值原样返回，所以后端的语义层常量 `no_data` 会以英文标识符形态出现在中文和日文页面上。加一条映射到 `diagnosticNoData` 三语词条。

### 2.4 信号表的截断不再无声

`buildPriorityRows` 写死 `.slice(0, 6)`，而表头显示的是**全部**信号数。18 条信号时页面写着 18、列出 6 条、不说少了 12 条——正是这个面板本身要暴露的那类采样缺口。

- 抽出 `PRIORITY_ROW_LIMIT`，视图模型多返回 `hiddenSignalCount`，表头追加「{count} more not shown」。
- 同时把 signals 按 severity 排序后再截断。原来是 `[...anomalies, ...gaps]` 直接拼接，**六条 info 级 anomaly 就能把全部 warn 级 evidence gap 挤下表**。排序是稳定的，同级仍保持后端顺序。

### 2.5 删掉一段算了没人读的前端代码

`diagnosticBaselineRows` 在真实 baseline 后面追加一条合成的 `prediction_safe_status` 行，而下游只按 key 取那三格——这条行从来没有被任何一格消费过。连同它独占的三个 i18n 词条（`predictionSafeStatus`/`predictionUnavailable`/`predictionUnavailableDetail` × 3 语言）一并删除。

（页面上的「不做预测」承诺由 `diagnosticNoForecastBadge` 徽章表达，那个是真的在渲染的。）

### 2.6 六格的版面

`grid-template-columns: repeat(3, ...)` 写死在两处。改为 `repeat(auto-fit, minmax(112px, 1fr))`（窄屏 96px）——430px 的 popover 放不下六个 20px 等宽数字，自动折成两行；dashboard 宽度下仍是一行。**写死列数意味着每加一格都会静默挤压既有格子。**

## 3. 新增的两道门

都在 `diagnostics_surface_test.go`，都是 Go 侧读 TS 源文本（`ui/` 没有 JS 测试运行器，`package.json` 只有 dev/build/preview/typecheck；沿用 `capability_matrix_test.go` 已验证过的形状）。

| 门 | 断言 | 会在什么时候救人 |
|---|---|---|
| `TestEveryDiagnosticBaselineReachesThePanel` | `buildDiagnosticBaselines` 产出的每个 key 都在 `diagnosticModel.ts` 里被字面量引用 | 后端加 baseline 而前端忘记渲染——**即本次缺陷** |
| `TestEveryDiagnosticSignalKindHasLocalizedCopy` | 每个 signal kind 在每个 locale 都有 `diagnosticSignal<Kind>Title`/`Detail` | 加 signal 忘加三语文案（UI 丢弃 Go 侧 Title，只按 kind 反查 i18n） |

两道门都**不维护清单**：signal kind 用正则从 `diagnostics.go`/`observer.go` 扫，locale 按 `^  xx: {` 分块扫（加第四种语言自动纳入），baseline 直接调 `buildDiagnosticBaselines`。**需要和被测变更同步手改的清单，正是这两道门存在的理由要绕开的东西。**

**变异验证（两道都红过）**：

| 注入 | 结果 |
|---|---|
| `byKey.get("evidence_walk_cost")` → `..._TYPO` | 如期失败，打印 `baseline "evidence_walk_cost" ... never named in ui/src/diagnostics/diagnosticModel.ts` |
| 删掉 en 的 `diagnosticSignalProcessObservationIncompleteTitle` | 如期失败，打印缺失的 key 与 locale |

第二道门**首次运行就抓到一个真缺口**：`process_observation_incomplete` 这个 warn 级 signal 在三语里一条文案都没有（其余 22 个 kind 齐备）。它一旦触发（OS 进程查询失败）就会以 `process observation incomplete` 的裸标识符形态出现在页面上。已补三语。

### 4.2 渲染层实测又抓到两条同类虚构（都不是本轮新加的）

**这正是「在渲染层验」的回报——两条都在 API 层看不出来。**

1. **已测到的 0% 被报成 "n/a"。** `coverageDetail` 写的是 `if (pct === null || pct <= 0) return t("unavailable")`。冷启动时 `active_session_ratio = "0 of 72"` 是**一次成功的测量**，结果副标显示「n/a」。这是 D-029 附带四的**镜像**：那条讲「用零表示算不出」，这条是「用算不出表示零」。改为只有 `pct === null` 才 unavailable。
2. **`max(2%, var(--metric-pct))` 的下限本身就是虚构。** 实测 0% 的格子画出 2% 的条。之前只把新格子绕开了这个坑，没有拔掉坑。改为 `width: var(--metric-pct)`，实测零就画零。

**教训**：`percent: number | null` 的类型改造解决了「没有分母」，但没解决「分母有、分子是零」。**两种零必须分开，而 CSS 的下限值会把它们重新合并。**
