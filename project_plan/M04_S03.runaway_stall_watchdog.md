# M04_S03 · 失控/卡死看门狗（文档化阈值）

## OKR

- **Objective**：让灾难在第一圈循环时可见——每条线索自报证据来源与阈值，误报被 fixture 门死，停止永远由人显式触发。
- KR1：模拟卡死会话与燃烧异常各自端到端跑通：线索 → 通知（存在规则时）→ 用户显式停止。
- KR2：正常长跑对照 fixture 零线索（误报门）。
- KR3：看门狗新增空闲 CPU <0.2%（perf gate）。

## Checklist

- [ ] 实现观测式线索：token 燃烧斜率偏离会话自身基线；进程存活但 transcript 无移动超用户可调阈值；subagent spawn 速率突增；孤儿/僵尸进程
- [ ] 每个阈值先写入 docs/neutral-observation-principles.md 标准再上码；UI 中每条线索显示证据来源与阈值
- [ ] 扩展既有 diagnostics 异常信号架构（diagnostics.go），不另起平行系统
- [ ] 向 M03_S04 通知引擎追加看门狗规则类型
- [ ] 线索接入 M03_S03 显式停止动作——断路器永远是人，绝不自动发信号
- [ ] 构建 fixture 场景：stuck-running、loop-burn、orphan，外加一个正常长跑对照

## 验收标准（量化）

1. 模拟 stuck 会话与 burn 异常各产生 线索 → 通知（有规则时）→ 用户发起停止成功 的端到端链路。
2. 每条线索显示其阈值与证据来源；审计证明零条无成文标准的判断性文案。
3. 正常长跑对照 fixture 零线索产生（误报门——"stuck vs working"之辨必须精确，否则比没有更糟）。
4. 看门狗空闲 CPU 增量 <0.2%（M02_S02 perf gate 复用）。
